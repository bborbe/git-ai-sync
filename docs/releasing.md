# Releasing

GoReleaser builds the release artifacts; it does not create the Release.

## The sequence

1. Merge to `master`. `.maintainer.yaml` sets `release.autoRelease: true`, so the
   releaser rewrites `## Unreleased` into `## vX.Y.Z`, commits, tags and pushes.
   **This creates a tag, not a Release object.**
2. Promote the tag to a Release:

   ```bash
   gh release create <tag> --verify-tag --generate-notes --target master
   ```

3. `.github/workflows/release.yml` fires on `release: [published]` and runs
   `goreleaser release --clean`, which uploads `git-ai-sync_<os>_<arch>.tar.gz`
   for darwin and linux on amd64 and arm64, plus `checksums.txt`, and pushes the
   generated cask to `bborbe/homebrew-tap`.

## Why the promotion step is manual

The Release is the human gate. `autoRelease` fires on every merge to `master`, so
a workflow triggered on tag push would publish a Homebrew cask for every merge and
skip that gate. `release: [published]` is what makes the promotion deliberate —
the same shape `dark-factory` uses (see its `docs/releasing-dark-factory.md`).

Deleting `.github/workflows/release-wheel.yml` removed the repo's only other
`gh release create`, so step 2 is now the sole path from a tag to a Release. It is
not optional: without it, nothing fires and the tag carries no assets.

## Requirements

- GoReleaser **>= v2.19** — `.goreleaser.yaml` uses `homebrew_casks.hooks.post.install_steps`,
  which replaced the deprecated raw-Ruby `hooks.post.install` hook in v2.19.
  `release.yml` pins `v2.19.0`; `ci.yml` validates the config against the same version.
- `HOMEBREW_TAP_TOKEN` as a repo secret in `bborbe/git-ai-sync`: a fine-grained PAT
  scoped to `bborbe/homebrew-tap` only, with Contents read/write.

## The cask

`bborbe/homebrew-tap`'s `Casks/git-ai-sync.rb` is now generated by GoReleaser and
committed by `goreleaser-bot`. Do not hand-edit it, and do not run the tap's
`update-git-ai-sync-cask.yml` — that workflow rewrites the retired wheel cask and
must be deleted in the tap.

The generated cask installs the binary and does **not** register a launchd agent.
The hand-maintained wheel cask it replaced did (`setup-launchd` postflight);
re-registration is tracked separately.
